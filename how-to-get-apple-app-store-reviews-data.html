How to Get Apple App Store Reviews as Structured Data

8 Nov 2026 · benthepythondev

Reading App Store reviews one at a time in the store doesn't scale once you're tracking more than one app or more than one country. The App Store Reviews Scraper pulls reviews for any iOS or macOS app and gives you one row per review. You give it app IDs or full App Store URLs (it pulls the ID out of the URL) and a list of country storefronts. It reads the App Store's own review data, so you don't need a browser, a login or an API key.

Tracking Android apps too? See how to get Google Play reviews as structured data.

What you get

Each review comes back as one row with these fields:

  • rating: the star score, 1 to 5
  • title and content: the review headline and the full review text
  • author_name and author_uri: the reviewer's display name and a link to their reviews
  • version: the app version the review was written for
  • vote_count and vote_sum: helpfulness vote data for the review
  • country: the storefront the review came from
  • updated_date: the date and time of the review
  • app_id, app_name and app_url: which app the review belongs to
  • review_id: a stable ID for the review, which monitor mode uses to tell new reviews from ones it has already seen

The README also lists review_date, is_edited, average_user_rating and user_rating_count. None of those were in the sample run below, so don't assume every row will have them.

You can export results as JSON, CSV or Excel, or view them as a table in the Apify Console.

Use cases

Sentiment analysis for product teams. Pull a large batch of reviews for your app and run them through whatever text analysis you already use. Because each row has the version field, you can see how feedback changed after a release.

Competitor comparison. Pass several app IDs in one run, for example ["333903271", "389801252"], along with the same set of countries. You get reviews for all of them in one dataset and can compare ratings and complaints side by side.

Alerts for new 1-star reviews. Turn on monitorMode, set minRating and maxRating to 1, save the input as a Task and put it on a schedule (every 6 hours, say). Every run after the first one saves only reviews written since the previous run. Add a webhook or the Slack or email integration on "Run succeeded" and you'll get a message whenever a new 1-star review appears.

Filtering by stars. "minRating": 4 gives you only 4 and 5 star reviews, which is handy for picking out praise. A low maxRating gives you only the complaints. Reviews outside the range aren't saved and aren't charged.

How to run it on Apify

  1. Open the actor page on Apify.
  2. Enter appIds or appUrls, plus countries (for example ["us", "gb", "de", "jp"]).
  3. Set maxReviews per app per country, and choose sortBy: mostRecent, mostHelpful or both.
  4. Start the run, then export the dataset or read it through the Apify API. You can also connect it to Make, Zapier or n8n.

Example input:

{
  "appIds": ["333903271", "389801252"],
  "countries": ["us", "gb", "ca"],
  "maxReviews": 300,
  "sortBy": "mostRecent"
}

Use it as an API on RapidAPI

If you'd rather call it as a plain HTTP API with RapidAPI keys and billing, it's also listed at App Store Reviews Scraper on RapidAPI.

Honest limits

  • Review caps. You can get at most 1,000 reviews per app per country. With sortBy: both the limit is 2,000, because the scraper reads both lists and removes duplicates. If you set maxReviews to 0, you get 500. For apps with years of reviews, that means you won't get the full history.
  • The first monitor run saves nothing. It only records which reviews already exist. Set maxReviews higher than the number of reviews the app gets between two runs, because the feed is read newest first and anything past the cap is missed.
  • Each app and country is tracked on its own. When you add a new country, it needs its own baseline run before it starts reporting new reviews.
  • Fields can vary. The sample rows didn't match the README's field list exactly, so check a small run before you build anything that depends on specific fields.
  • Personal data. Reviewer names and profile links are personal data. You're responsible for having a lawful basis under the GDPR and similar laws, collecting only what you need, and not using the data for unsolicited marketing.
  • Country count. The README says 48 storefronts in one place and "50+" in another. Test the country codes you need before you rely on them.

To start, run it once for one app in one country and look at the rows you get back.
