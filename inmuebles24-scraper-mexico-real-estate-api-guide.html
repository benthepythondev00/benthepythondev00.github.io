Inmuebles24 Scraper: a buyer and integration guide for Mexico real estate data

26 Nov 2026 · benthepythondev

The short answer

The Inmuebles24 Scraper takes public search result URLs from Inmuebles24, a major Mexican real estate marketplace, and returns structured property listings. Each listing comes with price, area, room counts, location, photos, and the publishing agency's public contact data. It suits analysts, brokerages, relocation and acquisition teams, and developers who need Mexican listing data in a spreadsheet, database or app. You can run it on Apify or call it as an API on RapidAPI.

If you searched for an "inmuebles API": Inmuebles24 has no public listings API, and this Actor fills that gap. You send it a search URL and get JSON back.

What you get

Each row is one unique public Inmuebles24 posting. In plain words:

  • Identity: stable posting id and code, the canonical url, title and generated_title, plus a clean description.
  • Type and deal: property_type, posting_type, and operation (sale, rent or another advertised operation).
  • Price: price, currency, formatted_price, every price and currency combination in prices, and maintenance expenses when listed.
  • Size and layout: total_area_m2, covered_area_m2, land_area_m2, rooms, bedrooms, bathrooms, parking_spaces, age.
  • Location: address, neighborhood, city, province, and latitude / longitude when the source provides them.
  • Publisher: agency_id, agency, agency_url, agency_phones, whatsapp, agency_logo, agency_license, agency_type.
  • Media: image, images, and the flags has_video, has_tour, has_plans.
  • Context: lead_score (a public data completeness score), source_page, search_rank, source_total_results, modified_at, scraped_at.

If a field is missing on the source, it stays empty. The Actor does not guess prices, contacts, coordinates or room counts.

Real example output

Here is the row from the most recent real call we have:

[
  {
    "status": "no_results",
    "message": "The run finished and found no results for this input."
  }
]

When a search URL matches no listings, the run ends cleanly and returns one status row, not an error. You can catch this case in code by checking status. A run that finds listings returns one row per posting, with the fields listed above.

Commercial use cases

  1. Price comparison and market research. Compare asking prices by municipality, neighborhood, operation and property type, for example apartments for sale in Ciudad de México against houses for rent in Querétaro.
  2. New listing and price change alerts. Run saved searches on a schedule and diff them on id and price to catch new inventory and price moves in the markets you care about.
  3. Brokerage intelligence and agency lead lists. Track which agencies are active and compare their visible portfolios, using the public phone and WhatsApp values shown on the listing.
  4. Feeds for apps and workflows. Send listings to a spreadsheet, database, dashboard, CRM, Make, Zapier or n8n. You can also map listings that have coordinates, or keep snapshots before inventory changes or is removed.

When to use this vs manual export or your own scraper

  • Manual copying works for a handful of listings. It does not scale across pages, and it gives you no stable IDs to track changes over time.
  • Writing your own scraper means you handle pagination, parsing Mexican feature labels into room counts, deduplication and ongoing maintenance yourself.
  • This Actor keeps the site's own filter model, because you paste the URL you already set up on Inmuebles24. It follows pagination, deduplicates by posting ID across all URLs in a run (so an overlapping property is saved and billed once), and exports to JSON, CSV, Excel or XML.

How to run it

On Apify: open the Inmuebles24 Scraper on Apify, set your filters on Inmuebles24, copy the results URL, and paste it in:

{
  "searchUrls": [
    { "url": "https://www.inmuebles24.com/departamentos-en-venta-en-ciudad-de-mexico.html" }
  ],
  "maxResultsPerSearch": 50,
  "maxPagesPerSearch": 5
}

The default run stops at 10 rows to keep first runs fast. Raise maxResultsPerSearch and maxPagesPerSearch for larger exports. You can schedule recurring runs or read the dataset through the Apify API.

As an API on RapidAPI: call it through the Inmuebles24 Scraper API on RapidAPI using your RapidAPI key. The input fields are the same.

FAQ

Is there an Inmuebles24 API?

Inmuebles24 does not offer a public listings API. This Actor works as one: you send search URLs and get structured JSON rows back, on Apify or RapidAPI.

Can I filter by city, price or bedrooms?

Yes. Apply the filters on the Inmuebles24 website and paste the resulting URL. Whatever the URL represents is what gets collected.

Can I run several searches at once?

Yes. Put several URLs in searchUrls. Duplicate postings across them are removed.

What does lead_score mean?

It scores how complete the public data on a listing is. It does not predict whether someone will buy.

Why did I get a no_results row?

Your search URL matched no listings when the run happened. Check the URL in a browser and loosen the filters.

Honest limits

  • It only covers public Inmuebles24 Mexico search results. It does not log in or reach private data.
  • Fields depend on what each publisher filled in. Coordinates, area, expenses and contacts are often empty.
  • A narrow or outdated search URL can return no results, as in the example above.
  • The default limit is 10 rows per search, so raise it for real exports.
  • Output can include personal data such as agent names and phone numbers. You are the controller of that data: you need a lawful basis under the GDPR and similar laws, you should collect only what you need, and you should not use it for unsolicited marketing.
