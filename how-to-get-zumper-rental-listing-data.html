How to get Zumper rental listing data (and track rent changes)

26 Oct 2026 · benthepythondev

If you need rental listings from Zumper in a spreadsheet or a database, the Zumper Rental Scraper on Apify exports them by city, property type, price and bedroom count. It can also watch a saved search and return only listings that are new or whose asking rent changed. Output comes as JSON, CSV or Excel.

What you get

Each row is one Zumper listing or building. These are the fields in the sample run below:

  • Identity and link: listing_id (stable across runs), url, name, source and scraped_at.
  • Location: the full address plus street, city, state, zipcode, neighborhood, and latitude / longitude.
  • Rent and size: price_min and price_max (monthly asking rent range for the building), beds_min / beds_max (0 means studio) and baths_min / baths_max.
  • Details: property_type, the source rating, a list of amenities, pets_allowed, date_available and has_fees.
  • Contact: phone, agent_name, brokerage_name and feed_name, when Zumper shows them.
  • Photos: image_ids and image_count. Turn on includePhotos to get photo URLs where they're available.
  • lead_score: a 0 to 100 heuristic based on how complete the listing is, useful for sorting.

If a field isn't on the source listing, it stays null or empty.

What people use it for

  • Rental comps and market studies. Pull every apartment in a city within a price band, then compare rent ranges by neighborhood or zip code using the address and coordinate fields.
  • Portfolio monitoring. Schedule a weekly run on the markets you care about and keep the rent and availability snapshots over time.
  • Price change alerts. Turn on onlyChanges, and each run returns only rows marked new, price_changed or details_changed in a change_type field. Where the values exist, those rows include the previous asking rent and the size of the change. Unchanged listings are left out.
  • Automated workflows. Connect the dataset to n8n, Make or Zapier. The README links an n8n rental alert template you can start from.

Two write-ups show change mode on real runs: the Austin change-only feed (baseline, duplicate suppression and n8n delivery over six runs) and the San Francisco rent drop it caught overnight.

How to run it on Apify

Open the actor page and set the input. A small one-off export looks like this:

{
  "mode": "search",
  "location": "san-francisco-ca",
  "propertyType": "apartments-for-rent",
  "maxListings": 3,
  "includePhotos": false,
  "useApifyProxy": true
}

location is a city-state slug such as austin-tx. You can add minPrice, maxPrice, minBeds and maxBeds, or switch mode to direct_urls and pass specific Zumper links in listingUrls. maxListings defaults to 10.

For a recurring monitor, add "onlyChanges": true, a stable monitorId such as "austin-rentals-under-3000", and pick a firstRunMode. With seedOnly, the first run saves a baseline and returns nothing, and later runs return only what changed. With emitAll, you get the baseline back on the first run as well. Then schedule the run in Apify.

How to call it as an API on RapidAPI

If you'd rather make a plain HTTP request than use the Apify console, the scraper is also listed on RapidAPI: Zumper Rental Scraper API. It takes the same search inputs and returns the same listing fields.

Honest limits

  • Prices are building ranges. price_min and price_max cover the whole building. They don't mean every unit matches your filters, or that a unit is still available. Check the exact unit and terms with the listing provider.
  • Some fields are often empty. date_available is null in all three sample rows. Phone, agent and brokerage only show up when Zumper exposes them.
  • lead_score is only a sorting aid. It doesn't verify a landlord, judge whether something is a good investment, or tell you anyone will answer the phone. Ratings and contact details are whatever the source says.
  • airbnbFriendly just passes Zumper's own filter through. It's not a legal check on short-term rental eligibility.
  • Cost grows with output. On the free tier it's $0.015 per returned listing, plus $0.01 for each listing that has a phone number. That phone charge applies automatically whenever phone is present. On a 512 MB run there's also a $0.00005 start event. Set maxListings and Apify's maximum run charge before you start a large export. In monitor mode you're only charged for the change rows a run returns, so an unchanged repeat costs only the start event.
