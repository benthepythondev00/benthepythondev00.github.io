How to get tech company job listings from Greenhouse

15 Nov 2026 · benthepythondev

Many tech companies post their open roles on Greenhouse, a hiring system that hosts their career pages. The Greenhouse Jobs Scraper on Apify reads those boards through Greenhouse's official public job-board API and gives each role back as one structured row. You don't need a login or an API key.

You can use the built-in list of 40+ tech employers (the README names Stripe, Airbnb, Cloudflare, Discord, Figma, Notion, Uber, Coinbase and Databricks). You can also pass your own Greenhouse company tokens, which are the short slugs like stripe or cloudflare.

What you get

Each job comes back with these fields:

  • job_id: the stable ID of the listing
  • job_title: the role title
  • company_name and company_token: the employer and its Greenhouse slug
  • location: the location text as the company wrote it
  • remote_flag: true or false, detected automatically
  • departments: a list of the teams the role belongs to
  • employment_type: Full-time, Internship, Contract and so on, when the board publishes it
  • posted_date: when the listing was last updated, as an ISO timestamp
  • job_url: the direct link to the listing and apply page
  • job_description: the full description text, only when includeDescription is turned on
  • source and scraped_at: the source label and the time of the run

If you turn on includeDescription or set remoteScope, each row also gets remote_scope, is_hybrid, visa_sponsorship and timezone_requirement. These fields tell you who can actually apply for a "remote" role, for example US only or EMEA only.

Use cases

Feeding a job board. If you run a job board, you can pull fresh listings from many employers on a schedule rather than browsing career pages by hand. Every row includes the apply URL.

Recruiting and sourcing. A recruiter can filter by title keywords like engineer or devops and by location, so they get only the roles that matter to them.

Talent intelligence. The departments, locations and posting dates show which teams a company is hiring for and where.

Finding roles that are really remote. Set remoteOnly to true, then use remoteScope (for example worldwide or country:US) to keep only roles open to the people you care about. You can also check visa_sponsorship and timezone_requirement. For remote roles from job boards outside Greenhouse, see how to get remote job listings from six job boards.

Honest limits

  • It only covers Greenhouse. Companies that hire through a different system won't show up, and to add a company you need to know its Greenhouse token.
  • Employment type is often missing. Many boards don't publish it, Stripe included. The README says the field is null in that case and is never guessed. In the real rows above, it came back as "Unknown", so your code should handle both.
  • Descriptions cost time. You only get job_description and the remote eligibility fields with includeDescription on, and the README says that makes runs slower.
  • The remote fields come from keyword rules, not a model. If a sentence doesn't match the rules, the result is unspecified. Treat it as a filter and not as a final answer.
  • posted_date is the last update. It tells you when the listing was last changed, which may not be when it was first posted.
  • Departments are the company's own labels. Stripe's example is "8611 Security Analytics", so one company's names may not line up with another's.
