How to Get Google Play Reviews as Structured Data

31 Oct 2026 · benthepythondev

If you want to read what users say about an Android app, the Google Play page works for a handful of reviews. For hundreds or thousands, you need them in a file you can sort, filter and analyse.

The Google Play Reviews Scraper does that. You give it one or more app package IDs or Google Play URLs, and each review comes back as one row. You don't need a login or an API key, and it reads Google Play's review data directly instead of driving a browser.

What you get

Each row describes one review:

  • review_id and review_date: the review's identifier and when it was posted
  • rating: the star rating, from 1 to 5
  • content: the full review text
  • author_name and author_image: the reviewer's display name and a link to their photo
  • thumbs_up_count: how many other users marked the review as helpful
  • app_version: the app version the review was written on
  • app_id, app_name and app_url: which app the review belongs to
  • country: the store the review was collected from
  • reply_content and reply_date: the developer's reply and its date, when the developer has responded

What people use it for

  • App store optimization: track review sentiment and pull out common complaints and feature requests for your own apps.
  • Sentiment analysis: build NLP or machine learning datasets, or watch brand perception over time.
  • Competitor research: compare review volume and ratings across rival apps, then read their negative reviews to find weak spots.
  • Market research: look across an app category or niche and spot gaps from what users actually ask for.

How to run it on Apify

  1. Open the actor page on Apify.
  2. Add your apps in appIds or paste full links into appUrls. The package ID is the id= part of the Google Play URL, so https://play.google.com/store/apps/details?id=com.twitter.android gives you com.twitter.android.
  3. Set countries, language and maxReviews. The default for maxReviews is only 5, so raise it for a real dataset.
  4. Optionally choose a sortBy value (newest or most_relevant) and a filterRating.
  5. Run it, then view the results as a table or export them as JSON, CSV or Excel.

This input collects up to 500 of the newest 1-star English reviews for each app in each country, which is a good start for studying complaints:

{
  "appIds": ["com.twitter.android", "com.instagram.android"],
  "countries": ["us", "gb"],
  "language": "en",
  "maxReviews": 500,
  "sortBy": "newest",
  "filterRating": 1
}

Honest limits

  • Developer replies are not always there. You only get reply fields when a developer has answered, so expect many rows without them. Your code should handle those fields being missing.
  • maxReviews applies per app and per country. The cap is 100,000, and 0 also means 100,000. Two apps across two countries at 500 each can return up to 2,000 reviews, so the cost grows with each app and country you add.
  • filterRating takes one star rating. To get both 1-star and 2-star reviews, plan on separate runs.
  • Short reviews carry little signal. Rows like "nice" count as reviews, so filter on text length if you're doing text analysis.
  • The app version may not be the current one. The rows above, collected within minutes of each other, show both 12.31.0-prod.01 and 10.16.0-release.0. Group by app_version before blaming a recent release for a complaint.
  • Countries are limited to the supported stores. The README lists 50+ country codes, including us, gb, de, jp and in.
  • Request pacing matters. delaySeconds adds a delay between requests to avoid rate limits, and the default is 0.5.
  • Rows include reviewers' names and photo links. Drop author_name and author_image if your analysis doesn't need them.
