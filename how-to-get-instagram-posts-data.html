How to get Instagram posts data from any public account

11 Nov 2026 · benthepythondev

If you need the posts of a public Instagram account in a spreadsheet or a database, copying them by hand doesn't scale. The Instagram Posts Scraper exports an account's posts and reels, newest first, as structured records. It doesn't log in and needs no cookies or Instagram API key. It asks Instagram for the same data its website loads for a visitor who isn't logged in.

What you get

Each post or reel is one record. Here are the fields, grouped:

  • The post itself: id, the short code, the public url, the caption, posted_at (UTC timestamp) and media_type (image, video or carousel). record_type tells you whether it's a post or a reel. Flags show whether the post was edited, is pinned to the grid, or is marked as a paid partnership.
  • Engagement: likes, comments, and likes_hidden, which is true when the author hid the like count.
  • Author: username, full_name, author_id, is_verified, plus from_profile, the account whose grid the post came from. That matters for collaboration posts.
  • People and places: mentions (handles written in the caption), tagged_users, coauthors (collaborators), location_name and location_id.
  • Content: hashtags, image_url, video_url and slide_urls for carousel slides.
  • Audio on reels: music_title and music_artist.
  • Extras: alt_text and scraped_at.

What people use it for

The README lists these use cases:

  • Competitor and brand monitoring. Schedule a daily run with postedAfter set to yesterday. Each run then collects only the new posts from the accounts you watch.
  • Content analysis. Compare likes and comments by format, hashtag, collaborator and posting time. media_type, hashtags, coauthors and posted_at are already split into their own fields for this.
  • Influencer vetting. Look at real engagement on recent posts instead of relying on a follower count.
  • Datasets for AI and research. Captions with dates, tags and alt text work for classification, trend studies or RAG.

How to run it on Apify

Open the Instagram Posts Scraper on Apify and fill in the input:

  • usernames: usernames, @handles or profile links
  • maxResults: posts per account, newest first (20 by default, up to 100,000)
  • postedAfter / postedBefore: an optional UTC date window in YYYY-MM-DD format

This example gets everything two accounts posted in September 2026:

{
  "usernames": ["natgeo", "nasa"],
  "maxResults": 1000,
  "postedAfter": "2026-09-01",
  "postedBefore": "2026-09-30"
}

When postedAfter is set, reading stops as soon as the scraper reaches older posts, so daily runs stay small. You can export the results as JSON, CSV or Excel, run it on a schedule, call it through the Apify API, or connect it to Make, Zapier or n8n.

Pricing is per saved post plus a small start fee per run. It's $1.50 per 1,000 posts on the free plan and less on paid plans. The README puts the default 20-post run at 3 cents. If you set Maximum cost per run in the run options, the Actor stops saving at that amount and says so in the status message.

Honest limits

  • Public accounts only. The scraper never logs in, so it can't see private accounts.
  • Media links expire. Instagram signs image_url, video_url and slide_urls, and the links stop working after some hours. Download the files soon after the run if you need them.
  • Some fields are often empty. In the example rows plays, location_name and alt_text are null. Whether a field is filled depends on the post.
  • maxResults counts per account, not per run. Three usernames with maxResults: 100 can return up to 300 records.
  • Rate limits on long exports. Instagram limits how much one address can read. The README says the Actor then continues through another address without starting over, but very large exports still take longer.
  • Tags can repeat. In one example row, tagged_users lists hulu, twhiddleston and disneyplus twice each. Remove duplicates if you count them.
