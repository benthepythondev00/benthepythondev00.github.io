yfinance alternative: a watchlist's quotes, P/E and financials in a spreadsheet

27 Oct 2026 · benthepythondev · Last checked 27 Oct 2026 with live runs

To get quotes, valuation ratios and financials for a list of tickers into CSV or Google Sheets on a schedule, run the Yahoo Finance Scraper on Apify with your symbols. Save that input as a Task, schedule the Task, and read its last run as CSV from Python or with IMPORTDATA in Sheets.

Why not just run yfinance?

You can, and for a few tickers on your laptop it is the simplest option. The trouble starts when the script has to run unattended. The yfinance issue tracker has a long thread of people hitting YFRateLimitError('Too Many Requests'); one wrote "I keep getting the following error even from different IPs". Then the cron job fails quietly and the sheet goes stale.

To be clear about what this is: the Actor uses the yfinance library itself, inside its own container on Apify. What changes is where it runs and who keeps it working. You don't install, pin or patch anything, the requests don't leave from your machine, and you get one JSON record per ticker that exports straight to CSV.

The input

Tickers go in one string, comma-separated or one per line. dataTypes picks the blocks per ticker. For a fundamentals watchlist, quote and info are enough:

{
  "tickers": "MSFT, KO, NVDA, JNJ, XOM",
  "dataTypes": ["quote", "info"]
}

Add "financials" for income statement, balance sheet and cash flow, "history" with historyPeriod and historyInterval for candles, or "holders", "recommendations", "earnings", "dividends", "splits" and "news". The price per ticker is the same whichever blocks you pick.

Into a CSV with Python

Install the client with pip install apify-client (tested with version 3.4.0) and set APIFY_TOKEN to the token from Apify Console → Settings → API & Integrations. The script runs the Actor, waits for it and writes one row per ticker with the columns you name:

import csv
import os

from apify_client import ApifyClient

WATCHLIST = "MSFT, KO, NVDA, JNJ, XOM"
COLUMNS = ["price", "market_cap", "pe_ratio", "forward_pe", "price_to_book",
           "dividend_yield", "profit_margin", "debt_to_equity", "target_mean_price"]

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("benthepythondev/yahoo-finance-scraper").call(
    run_input={"tickers": WATCHLIST, "dataTypes": ["quote", "info"]},
    logger=None,
)
items = client.dataset(run.default_dataset_id).list_items().items

with open("watchlist.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["symbol", "name"] + COLUMNS)
    for item in items:
        values = {**item.get("info", {}), **item.get("quote", {})}
        writer.writerow([item["symbol"], values.get("name")] + [values.get(c) for c in COLUMNS])

On a schedule, into Google Sheets

  1. Open the Actor, enter your tickers and data types, and save the input as a new Task named, for example, my-watchlist (Apify docs on Tasks).
  2. In Apify Console go to Schedules, create a schedule with a cron expression such as 30 21 * * 1-5 (weekdays at 21:30 UTC, after the US close) and add your Task to it (Apify docs on schedules).
  3. In Google Sheets, put this in cell A1, with your username, Task name and token filled in: 
    =IMPORTDATA("https://api.apify.com/v2/actor-tasks/YOUR_USERNAME~my-watchlist/runs/last/dataset/items?status=SUCCEEDED&format=csv&fields=symbol,quote,info&omit=info.description&token=YOUR_TOKEN")

That URL always points at the Task's latest successful run, so the sheet follows the schedule without extra code. Nested blocks are flattened into columns named quote/price, info/pe_ratio and so on, and omit=info.description blanks out the long company description. Google refreshes IMPORTDATA on its own timing, not the moment a run ends.

Anyone who can open the sheet can read the token in that formula, so use a token you can revoke and keep the sheet private. If that is a problem, run the Python script on a schedule and upload the CSV instead.

Honest limits

  • Check your symbols. An unknown or delisted symbol still comes back as a row, with an empty quote block and every info field set to null, and today that row is charged like the others. The test symbol ZZZZQX did exactly that on 27 Oct 2026.
  • The data is Yahoo's. Fields are what Yahoo returns at run time. Some can be missing for a given company (a fund has no P/E, a stock without a dividend has no yield), so handle nulls.
  • It is still yfinance underneath. When Yahoo changes something that breaks the library, the fix lands as a new build of the Actor, not as an upgrade you make. Runs can still fail until that build ships.
  • Big lists run longer. Tickers are read one after another, so hundreds of tickers with financials or long history need more than the default 600-second run timeout.
  • Terms. Yahoo's terms of service govern how the data may be used. Read them for your use case; this page makes no claim beyond that.
