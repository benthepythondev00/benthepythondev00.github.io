How to get public Snapchat stories and highlights as structured data

12 Nov 2026 · benthepythondev

If you follow a set of public Snapchat creators and want their story snaps in a spreadsheet or a database, copying links by hand gets old fast. The Snapchat Stories Scraper reads the public profile page for each username you give it. It saves one row per snap, covering both the active story (when one is live) and the curated highlights pinned to the profile. You don't need a Snapchat login or an API key.

What you get

Each row is one snap. The fields fall into four groups.

Where the snap came from

  • source_type: active_story for the short-lived current story, or curated_highlight for snaps the creator pinned to their profile.
  • story_id, highlight_id, snap_id: the public identifiers, when Snapchat exposes them.
  • record_id: always filled. If Snapchat leaves out a snap ID (common for highlights), the Actor builds a deterministic key from the story, the snap index and the media URL, so the same snap gets the same ID on every run.
  • snap_index and rank: the snap's position inside its story or highlight.

The highlight or story itself

  • story_title, story_subtitle, story_emoji, story_thumbnail_url, story_type.

The media

  • media_type (for example video), media_url, preview_url, and, when present, overlay_url, attachment_url and transcript_url.
  • published_at: the timestamp for the snap.
  • Other per-snap fields such as snap_title, snap_subtitles, is_sponsored, latitude and longitude. Snapchat often leaves these empty.

The creator

  • creator_username, creator_name, creator_url, creator_profile_picture_url, creator_subscriber_count, creator_badge, creator_category, creator_subcategory, creator_bio.

Every row also carries source_url and scraped_at.

What people use it for

The README lists these uses, among others:

  • Watching a creator list. Run it on a schedule against a set of usernames to see which public stories are live right now.
  • Spotting changes between runs. Because record_id stays the same for the same snap, you can compare two snapshots and see which snaps were added or removed.
  • Building a research table. Combine snap order, timestamps, media type and creator category and bio into one table you can review.
  • Passing media to your own tools. Send the image, video, preview, attachment or transcript URLs into an internal workflow, keeping ephemeral stories apart from durable highlights by filtering on source_type.

How to run it

On Apify

Open the Actor page on Apify and give it input like this:

{
  "usernames": ["nasa", "jeremy-lynch"],
  "includeActiveStory": true,
  "includeCuratedHighlights": true,
  "maxProfiles": 10,
  "maxSnapsPerProfile": 15
}
  • usernames accepts plain usernames, @handles, /add/ links or snapchat.com/@... URLs.
  • maxProfiles and maxSnapsPerProfile both go from 1 to 100.
  • At least one of includeActiveStory or includeCuratedHighlights has to stay on.

You can export results as JSON, CSV or Excel, or pull them through the Apify API, webhooks or a scheduled run.

Honest limits

  • Public data only. The Actor reads what an anonymous visitor can see on a public profile. It doesn't sign in, it can't see friends-only snaps, and it doesn't get around audience controls. It also won't message, follow or post.
  • No full archive. You get what the profile shows at the moment of the run: the active story, if there is one, plus the curated highlights. Older stories that have expired are gone.
  • Active stories may be empty. Many profiles have no live story at a given time. The default nasa input is there because its highlights give you rows even when nothing is live.
  • The snap limit is shared. maxSnapsPerProfile counts active story and highlight snaps together, and active story snaps are handled first. With a low limit, highlights can get cut.
  • Lots of nulls. Fields like snap_title, is_sponsored, location and transcript_url are only filled when Snapchat provides them. In the example above they were all null.
  • Media links are CDN URLs. The README describes media_url and preview_url as current public Snapchat CDN resources. If you need the files later, download them yourself rather than counting on the link staying the same.
